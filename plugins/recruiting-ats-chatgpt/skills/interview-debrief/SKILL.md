# Итог собеседования → ATS

Результат интервью в ATS — это ответы на вопросы шаблона этапа и итог (`result`), которые сохраняются при переводе кандидата на этап (`transition_candidate`). Этот скилл превращает заметки интервьюера в такой результат. Методика и шкала — скилл `interview-design`; правила работы с ATS — скилл `recruiting-ats`.

## Процесс

1. **Кандидат и этап.** `search_candidates` / `get_candidate` → текущий этап и `allowedTransitions`. Этап, на который переводим, — тот, по которому проходило интервью: после HR-скрининга — `HR screening`, после технического — `Проф. интервью`, после финального — `Финальное интервью`. Если не очевидно — спроси.
2. **Шаблон.** `get_interview_context { candidateId, toStatus }` → шаблон этапа, обязательный или нет, вопросы и предпочтительные ответы.
3. **Ответы по вопросам.** Для каждого вопроса шаблона — строго в его порядке и с тем же текстом:
   - найди в заметках, что кандидат ответил; запиши кратко фактами (что сказал, какие примеры, что не смог);
   - если подходит предпочтительный ответ (уровень шкалы) — начни с него, затем детали: `Хорошо: объяснил поколения GC; про LOH не знал`;
   - вопрос не обсуждали — `skipped: true` с пустым ответом, **только если пользователь подтвердил**, что вопрос не задавался; иначе спроси;
   - не додумывай ответы и оценки: чего нет в заметках — уточни у пользователя.
4. **Итог (`result`)** — кратко, по структуре:
   ```
   Оценка: <компетенция> — 3/4 (<факт>); <компетенция> — 2/4 (<факт>) …
   Сильные стороны: …
   Риски: …
   Уровень: Middle (вакансия — Senior)        ← для технического этапа
   Рекомендация: Скорее да — <почему>
   Следующий этап: проверить <что>
   ```
   Рекомендация — одна из: **Нанимать / Скорее да / Скорее нет / Не нанимать**. Для скрининга также: условия (ожидания по доходу, формат, срок выхода, другие процессы).
5. **Комментарий к результату** (необязательно) — подробные заметки, которые не вошли в ответы, или ссылка на запись; сохраняется первым комментарием к результату интервью.
6. **Превью** (сложная форма → по умолчанию режим «превью»): кандидат, переход «этап → этап», шаблон, таблица «Вопрос | Ответ» (пропущенные — отмечены), итог, комментарий. Подтверждение.
7. **Сохранение.** `transition_candidate { candidateId, toStatus, interview: { templateId, answers, result, comment } }`. Ответь: новый этап, ссылка на карточку, кто ответственный дальше.

## Если результат отрицательный

Предложи, но не делай сам без подтверждения: либо сохранить результат этапа и затем отказ (две операции, две формы), либо сразу отказ (`toStatus: "Отказано"`) с причиной из справочника `rejectionReasons.responsible` и итогом в комментарии отказа. Выбор — за пользователем.

## Исправление сохранённого результата

`get_candidate` → `interviews` → нужный результат → новые ответы и итог → превью «было → стало» → `update_interview { id, result, answers }` (answers заменяют все ответы — передавай полный список).

## Несколько интервьюеров

Если заметки от нескольких человек — сохрани оценки каждого отдельно в итоге («Иванов: 3/4 …; Петрова: 2/4 …») и отметь расхождения; не усредняй молча. Общую рекомендацию формулирует пользователь.
