# Техническое интервью .NET-разработчика

Этап ATS — **Проф. интервью** (проводит проф. интервьювер кандидата). Цель — проверить не определения, а понимание и применение: как кандидат рассуждает, какие компромиссы видит, как пишет и читает код.

- Матрица тем по уровням — [references/topics.md](references/topics.md)
- Банк вопросов со шкалой — [references/questions.md](references/questions.md)
- Задачи: live coding, code review, system design — [references/practice.md](references/practice.md)
- Методика и шкала 1–4 — скилл `interview-design`; оформление итога — скилл `interview-debrief`; работа с ATS — скилл `recruiting-ats`.

## Структура интервью (60–90 минут)

| Блок | Время | Что |
|---|---|---|
| Опыт | 10 мин | Проект из резюме: архитектура, личная роль, самое сложное техническое решение |
| Основы | 15–20 мин | C#, CLR, async, коллекции — 3–4 вопроса по уровню |
| Веб и данные | 15–20 мин | ASP.NET Core, EF Core, SQL — 3–4 вопроса |
| Практика | 20–30 мин | Code review (Junior/Middle) или live coding; для Senior — system design |
| Вопросы кандидата | 5–10 мин | — |

Глубину задаёт уровень вакансии: начинай с вопроса уровня ниже целевого и поднимайся, пока кандидат уверенно отвечает. Не подсказывай сразу — сначала уточняющий вопрос («а что будет, если…?»).

## Шаблон «Проф. интервью» для вакансии

По процессу скилла `interview-design`:
1. Уровень и стек из вакансии (например, Middle .NET: ASP.NET Core, EF Core, PostgreSQL, RabbitMQ).
2. Из [references/questions.md](references/questions.md) — 8–12 вопросов, покрывающих блоки таблицы выше, с предпочтительными ответами-шкалой (`Сильно / Хорошо / Слабо / Не ответил` с сигналами). Последний пункт — «Практическое задание: <название>» с оценками `Решил сам, чисто` · `Решил с подсказками` · `Не решил`.
3. Теги: `Tech`, `.NET`, уровень, ключевые технологии.
4. Превью → подтверждение → `save_interview_template` → привязка к этапу «Проф. интервью» вакансии через `save_vacancy` (обычно обязательный).

## Персональный план по кандидату

1. `get_candidate`, `get_resume_text`, шаблон этапа (`get_interview_context { toStatus: "Проф. интервью" }`).
2. Вопросы шаблона — без изменений и в том же порядке (иначе ответы не сохранятся в ATS). Добавь 3–5 персональных вопросов по резюме: заявленные технологии («в резюме Kafka — как обеспечивали порядок и повторную обработку сообщений?»), проекты («как масштабировали сервис на X RPS?»), пробелы относительно требований вакансии.
3. Выбери практическое задание по уровню из [references/practice.md](references/practice.md).
4. Покажи план; предложи сохранить комментарием к кандидату (с подтверждением).

## Оценка

- По каждому блоку — балл 1–4 с фактами из ответов; итоговый уровень кандидата (Junior / Middle / Senior) может отличаться от уровня вакансии — это важно для решения и оффера.
- Сигналы Senior: говорит о компромиссах и цене решений, знает, как это устроено внутри, приводит примеры из эксплуатации (метрики, инциденты), предлагает, как проверить или измерить.
- Сигналы переоценённого уровня: заученные определения без примеров, «всегда используем X» без понимания почему, не может объяснить код из своего же резюме.
- Итог и перевод по этапу — скилл `interview-debrief`.
