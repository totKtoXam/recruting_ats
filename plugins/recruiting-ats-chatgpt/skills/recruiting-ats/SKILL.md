# Recruiting ATS

ATS — система подбора. Подключённый ассистент работает в ней **от имени пользователя** с его правами, и каждое изменение пишется в журнал ATS под его именем. Перед изменением покажи пользователю, что будет записано, и получи явное согласие на действие.

Воронка: `Новый ↔ HR screening ↔ Проф. интервью ↔ Финальное интервью ↔ Offer ↔ Hired`; «Отказано» — с любого этапа, вернуть из отказа можно только на тот этап, с которого отказали.

## Подключение

Если инструменты `recruiting-ats` недоступны, сообщи, что приватное приложение ChatGPT через Secure MCP Tunnel или локальный stdio-мост ещё не подключены. Не имитируй доступ и не предлагай OAuth-вход: текущий прокси ATS не пропускает `/.well-known/*`.

Плагин обращается к действующему `https://portal.devexpert.kz/hr-ats/mcp` через локальный stdio-мост. Туннель ChatGPT пересылает MCP-запросы этому мосту. Мост передаёт личный API-токен в `Authorization: Bearer` только ATS; токен задаётся как `ATS_MCP_TOKEN` вне репозитория и пакета. В ATS пользователь создаёт и отзывает токен в профиле, раздел «ИИ-ассистенты». Не проси прислать токен в чат и не помещай его в файлы плагина.

| Задача | Инструменты |

| Найти кандидата | `search_candidates` (ФИО, email, телефон, Telegram, №; фильтры по этапу, вакансии, источнику, ответственному; архив и корзина) |

| Перевод по этапу / отказ / возврат | `get_interview_context` → `transition_candidate`; правка результата — `update_interview` |
| Изменить карточку | `save_candidate` с `id` и только изменяемыми полями |

| Пользователи (админ) | `list_records` (`kind: users`), `save_user`, `set_user_access` |
| Аналитика | `get_dashboard` (7/30/90 дней), `get_notifications`, `set_candidate_watch`, `mark_notifications_read` |

## Правила

1. **ID не придумывай.** Бери их из `get_references` и `search_candidates`. Если по имени нашлось несколько записей — покажи варианты и спроси, какую взять.
2. **Сначала прочитай, потом меняй.** Перед изменением загрузи текущее состояние (`get_candidate`, `list_records`), чтобы показать «было → станет».
3. **Подтверждение перед каждой записью.** Инструменты без `readOnlyHint` меняют данные. Перед вызовом покажи пользователю форму (см. «Показ формы») и дождись явного «да» / «сохраняй» / «подтверждаю». Согласие на одно действие не распространяется на следующие. Если пользователь попросил изменить форму — покажи её снова.
4. **Пакетные действия** (несколько кандидатов, массовый отказ): одна сводная таблица всех изменений, одно подтверждение на весь пакет, затем вызовы по одному с отчётом об ошибках по каждому.
5. **Новый кандидат по умолчанию — черновик** (`create_candidate_draft`): пользователь проверит форму в ATS и нажмёт «Сохранить» сам. `save_candidate` без `id` создаёт кандидата сразу — только если пользователь прямо попросил «создай/сохрани кандидата» и подтвердил форму.
6. **Ошибки бизнес-правил** (обязательный шаблон, неверный телефон, вакансия не открыта, нет доступа к этапу) приходят текстом — объясни пользователю по-человечески и предложи, что исправить. Не обходи проверки.
7. **Персональные данные** кандидатов показывай только в этом разговоре: не публикуй их в общедоступные страницы, артефакты со ссылкой, внешние сервисы и файлы вне проекта без прямой просьбы пользователя.
8. Ссылки из ответов (`url` кандидата, `draftUrl`, файлы резюме) открываются после входа в ATS — давай их пользователю как есть.

## Показ формы перед записью

Есть два режима показа того, что будет записано:

- **Чат** — компактно прямо в ответе: заголовок действия, таблица «Поле | Значение» (при изменении — «Было | Станет»), предупреждения, вопрос «Сохранить?».
- **Превью** — визуальная форма в стиле карточки ATS: разделы, поля с подписями, изменённые поля подсвечены, незаполненные обязательные — отмечены, предупреждения сверху, кнопки «Подтвердить» и «Изменить».

**Режим по умолчанию** определяется сложностью формы:

| Чат (простые) | Превью (сложные) |
|---|---|
| комментарий и ответ, реакция, удаление комментария | карточка кандидата (создание, черновик, изменение нескольких полей) |
| архив / из архива / корзина / восстановление | перевод по этапу с ответами на вопросы шаблона |
| статус вакансии, источник | отказ (кто отказал, причина, комментарий) |
| подписка, отметка уведомлений | вакансия с привязками шаблонов к этапам |
| откат одного поля | шаблон интервью (вопросы, ответы, теги) |
| изменение 1–2 полей карточки | пользователь (этапы, права администратора), пакетные действия |

**Переключение по запросу пользователя.** «Покажи в чате», «без превью», «текстом» → режим «чат»; «покажи превью», «покажи форму», «визуально» → режим «превью». Выбор действует до конца разговора (или до следующей просьбы) и применяется ко всем формам, включая простые.

**Как построить превью** (подробные макеты — в [references/forms.md](references/forms.md)):

1. Если клиент поддерживает приватную встроенную визуализацию, отрисуй форму в ней; подтверждение принимай только после явного действия пользователя.
2. Иначе — оформи превью в чате как форму: заголовок, разделы, таблицы, эмодзи-метки (🟢 новое, 🟡 изменено, 🔴 обязательно, но пусто).
3. Не публикуй превью с персональными данными как общедоступный артефакт или страницу со ссылкой.
4. Для нового кандидата из резюме естественное превью — сам черновик ATS: после подтверждения данных создай черновик и дай `draftUrl`.
