# Сценарии работы с ATS

## 1. Резюме → кандидат

1. Файл резюме (PDF/DOC/DOCX до 10 МБ):
   - Если клиент может читать локальный файл и отправить его по одноразовой ссылке: `create_upload_link` → загрузи файл по выданному URL с именем (`?name=cv.pdf`) → передай `uploadId`. Ссылка живёт 30 минут; не показывай её в чате и не сохраняй в артефактах.
   - Если клиент поддерживает передачу содержимого файла в аргумент MCP-инструмента: передай небольшой файл в `file: { name, mimeType, base64 }`.
   - Если ни один способ недоступен, попроси пользователя прикрепить резюме в самой ATS. Не заявляй, что файл загружен.
   - Резюме текстом (вставлено в чат) — разбери сам, файла не будет: предупреди, что резюме нужно будет приложить в форме.
2. `parse_resume` — поля с уверенностью (`high`/`medium`), подсказки вакансии и источника (`hints`), дубли (`duplicates`). Не придумывай то, чего нет в резюме: отчество, зарплату, вакансию по одним навыкам.
3. `find_similar_candidates` по ФИО и контактам, если `parse_resume` не вернул дубли или данные вводились вручную. Найден дубль — покажи его и спроси, что делать (не создавать / всё равно создать / обновить существующую карточку).
4. `get_references` — вакансия, источник, рекрутер: подставляй, только если пользователь назвал их или совпадение однозначное.
5. Покажи форму кандидата (превью) → подтверждение.
6. По умолчанию `create_candidate_draft` → дай `draftUrl` («откройте, проверьте и нажмите Сохранить»). Если пользователь просил создать сразу и заполнены все обязательные поля — `save_candidate` без `id` и дай `url` карточки.
7. Ответ: ФИО, что заполнено, что осталось выбрать вручную, ссылка.

## 2. Перевод по этапу

1. Найди кандидата (`search_candidates` / `get_candidate`). Проверь `allowedTransitions`.
2. `get_interview_context { candidateId, toStatus }` — шаблоны вопросов для вакансии и этапа.
   - Обязательный шаблон: `templateId` и ответ на каждый вопрос **в том же порядке и с тем же текстом**; если вопрос не задавался — `skipped: true` с пустым ответом.
   - Необязательный: можно без шаблона (`templateId: ''`, `answers: []`).
   - Предпочтительные ответы шаблона предлагай как варианты, но не подставляй без согласия.
3. Ответы и итог бери из слов пользователя (заметки, расшифровка звонка). Не додумывай оценку кандидата — чего нет, спроси.
4. Превью формы перехода → подтверждение → `transition_candidate { candidateId, toStatus, interview: { templateId, answers, result, comment } }`.
5. Поправить результат позже — `update_interview { id, result, answers }` (id — из `get_candidate` → `interviews`).

## 3. Отказ и возврат

- Отказ: `toStatus: "Отказано"`, `rejection: { byType: candidate|responsible, responsibleId (для responsible — рекрутер, HR или проф. интервьювер кандидата), reason (из rejectionReasons[byType]), comment (обязателен для «Другое») }`.
- Возврат из отказа: `toStatus` = прежний этап (единственный в `allowedTransitions`), `comment` на верхнем уровне.
- Архивный кандидат переводиться не может — сначала `set_record_state { action: unarchive }` (отдельное подтверждение).

## 4. Изменение карточки

`save_candidate { id, ...только изменяемые поля }`. Пустая строка очищает необязательное поле; `links` заменяет весь список (передавай итоговый полный список); новое резюме (`resumeUploadId`) добавляет версию, старые остаются. Смена вакансии — только на открытую. Ответственные должны иметь доступ к своим этапам (см. `responsibles[].stages`).

## 5. Сводки и отчёты (только чтение, подтверждение не нужно)

- «Что у меня сегодня» — `get_dashboard` → `my.queue` (кандидаты на моём этапе), `stale` (зависшие > 14 дней), `get_notifications { view: unread }`.
- Воронка по вакансии — `search_candidates { vacancyId, limit: 100 }`, сгруппируй по `status`; для конверсий — `get_dashboard` (`funnel`, `vacancies.items`).
- Кандидат целиком — `get_candidate { includeStatusLog: true, includeComments: true }` + `get_resume_text`; сравнение с вакансией — только по фактам из резюме и интервью.
- Отчёт за период — `get_dashboard { days }`: KPI с прошлым периодом, источники, причины отказов, нагрузка по рекрутерам.
- Таблицы и графики строй по реальным числам из ответа; укажи период и дату формирования (`generatedAt`).

## 6. Массовые операции

Собери список (поиск/фильтр), покажи пакетную форму, одно подтверждение, затем вызовы по одному. Если часть упала — продолжи остальные и в конце покажи таблицу «успешно / ошибка с причиной». Не повторяй упавшие вызовы без исправления причины.

## 7. Справочники

- Вакансия: `save_vacancy` (без `id` — новая «Открыта»); статус — только `set_vacancy_status` по допустимым переходам.
- Шаблон: `save_interview_template` (вопросы/теги целиком); привязать к вакансии и этапу — `save_vacancy { id, name, templates: [...полный список...] }`.
- Шаблон вакансии (готовые этапы): `save_vacancy_preset { name, templates: [...] }`, из этапов существующей вакансии — `save_vacancy_preset { name, fromVacancyId }`. Новая вакансия по шаблону — `save_vacancy { name, presetId }` (ID — из `get_references.vacancyPresets`): этапы копируются один раз; `skippedStages` — этапы, где шаблон вопросов в архиве, они скопированы без вопросов.
- Архив/корзина: `set_record_state`; удалить можно только архивную запись и только админу; вакансию с кандидатами и пользователя-ответственного удалить нельзя.
