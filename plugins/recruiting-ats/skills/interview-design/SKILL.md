# Проектирование собеседований и шаблонов вопросов

Цель — **структурированное интервью**: всем кандидатам на роль задаются одни и те же ключевые вопросы, каждый вопрос проверяет конкретную компетенцию, а критерии оценки определены до собеседования. Это надёжнее «разговора по душам» и снижает предвзятость.

Методика — [references/methodology.md](references/methodology.md). Готовые банки вопросов: HR-скрининг — скилл `hr-screening`, техническое интервью .NET — скилл `tech-interview-dotnet`. Работа с ATS — по правилам скилла `recruiting-ats` (превью и подтверждение перед записью).

## Как шаблоны устроены в ATS

- **Шаблон** = название + список вопросов + теги (до 10, цвета `blue, green, amber, red, purple, teal, pink, gray`). У каждого вопроса — текст и **предпочтительные ответы**: интервьюер подставляет их одним кликом при заполнении результата.
- **Привязка**: у вакансии на каждом этапе — не больше одного шаблона, обязательный или необязательный (`save_vacancy.templates`). Шаблон этапа X заполняется при переводе кандидата **на** этап X (`get_interview_context { toStatus: X }`). Для обязательного шаблона нужно ответить на каждый вопрос или отметить его пропущенным.
- Один шаблон можно привязать к нескольким вакансиям — например, общий «HR-скрининг» для всех разработчиков и отдельные технические шаблоны по стеку.
- `save_interview_template` заменяет вопросы и теги **целиком**; изменение шаблона влияет на все вакансии, где он используется (проверь `list_records { kind: "templates" }` → `vacancies`).

## Как использовать предпочтительные ответы

В шаблоне нет отдельного поля «критерии оценки», поэтому шкалу кладём в предпочтительные ответы — интервьюер выбирает уровень одним кликом и при необходимости дописывает детали:

- Для технических и поведенческих вопросов — 3–4 уровня с сигналами, коротко (до ~150 символов):
  - `Сильно: <что назвал/показал>`
  - `Хорошо: <основное есть, пробел в …>`
  - `Слабо: <общие слова / ошибка в …>`
  - `Не ответил`
- Для фактических вопросов скрининга — типовые варианты: `Готов к офису`, `Только удалёнка`, `Выход через 2 недели`, `Есть оффер в процессе` и т. п.
- Текст вопроса — сам вопрос, который задаётся кандидату; при необходимости в скобках 1–2 уточняющих вопроса («…(уточнить: какая была нагрузка?)»).

## Процесс

1. **Контекст.** `get_references` → вакансия, её этапы и текущие привязки (`templateBindings`), существующие шаблоны (`templates` — не создавай дубль, предложи переиспользовать или доработать). Спроси, если не ясно: уровень (Junior/Middle/Senior/Lead), стек, ключевые задачи и must-have, формат работы, кто интервьюирует на каждом этапе, сколько времени на этап. Описание вакансии (JD) можно взять из ссылок вакансии или попросить у пользователя.
2. **Компетенции.** 4–6 компетенций роли и распределение по этапам:
   - HR screening — мотивация, ожидания, формальные условия, коммуникация, базовое соответствие резюме;
   - Проф. интервью — hard skills по стеку, решение задач, архитектура, качество кода;
   - Финальное интервью — ответственность, работа в команде, конфликты, лидерство, ценности и ожидания руководителя.
3. **Вопросы.** На каждую компетенцию этапа — 1–3 вопроса: поведенческий (реальный опыт, STAR), ситуационный (кейс), технический (для Проф. интервью). Держи шаблон в рамках времени этапа: ~5–7 минут на вопрос с уточнениями (HR screening 30 мин → 6–8 вопросов; техническое 60–90 мин → 8–12 вопросов плюс задача).
4. **Шкала.** Предпочтительные ответы по правилам выше.
5. **Теги.** Этап (`HR`, `Tech`, `Final`), стек (`.NET`, `SQL`), уровень (`Middle`, `Senior`).
6. **Превью** (режим «превью» по умолчанию): название, теги, таблица «Компетенция | Вопрос | Предпочтительные ответы», время этапа, в каких вакансиях будет использоваться. Отдельно — план привязки к этапам вакансии (обязательный или нет). Подтверждение.
7. **Сохранение.** `save_interview_template` для каждого шаблона → `save_vacancy { id, name, templates: [полный итоговый список привязок] }` — передавай и существующие привязки, иначе они удалятся. Покажи ссылку на вакансию или название шаблонов.

## Проверка существующего шаблона

Если просят «проверить/улучшить шаблон»: загрузи его (`get_references.templates` или `list_records`), оцени по чек-листу из [references/methodology.md](references/methodology.md#чек-лист-шаблона) и покажи таблицу «Вопрос | Проблема | Предложение». Правки — только после подтверждения; предупреди, в каких вакансиях шаблон используется.

## Нельзя

- Вопросы о возрасте, семейном положении и планах на детей, беременности, религии, национальности и этническом происхождении, здоровье (если не связано с работой), политических взглядах, финансовом положении. Трудовой кодекс РК запрещает дискриминацию в сфере труда.
- Вопросы-ловушки, головоломки, не связанные с работой, «проверка на стрессоустойчивость» грубостью.
- «Культурное соответствие» без определённых критериев.
